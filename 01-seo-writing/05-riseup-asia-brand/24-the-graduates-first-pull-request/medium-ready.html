The Graduate's First Pull Request

The graduate stared at the screen like it might bite. He was twenty-two, three weeks into his first job, and his first pull request, 30 lines of code for a small feature, sat open in front of the whole team. A senior engineer had left four comments. None of them were about the code working. All of them were about the code being understood: rename this, explain that, what happens when this fails? The graduate read each comment twice, changed the code, and pushed again. When the merge finally went through, the quiet ping of it landing sounded, to him, like a door opening.

Since rankings anchor this series, here is my openly editorial ranking of 5 things bootcamps should teach about AI, judged by one criterion: how much each lesson determines whether a graduate harvests AI value or gets harvested by it.

  1. Read every line the machine writes. This tops my list because unverified code is the root of nearly every AI incident. The graduate who reads is an engineer; the graduate who pastes is a liability with a keyboard.
  2. Tests are the price of admission. AI-generated code without tests is a rumor. Alim notes that a bootcamp graduate who writes tests for machine output is already in the top 5 percent of AI users.
  3. Know the failure modes by heart. Hallucinations, confident wrong APIs, plausible-but-broken logic: the graduate who has seen each one recognizes the next. Judgment is just scar tissue with a syllabus.
  4. Cost per run is your problem too. Every prompt bills someone, and the engineer who watches the meter designs leaner systems. Waste scales as fast as velocity.
  5. Own the merge. This ranks last only because it sounds soft. The graduate who signs the pull request, answers the 3 a.m. page, and fixes the bug becomes the senior. Ownership is the whole career, compressed into one habit.

None of this argues against AI in the hands of juniors. It argues for training that treats the machine as a power tool: magnificent, dangerous, and useless without the discipline to wield it. The bootcamps getting real results are the ones where graduates merge under senior review, learn why "what happens when this fails?" is the most important question in software, and build the testing habit before the prompting habit. That is evaluation before celebration in a code review, and retrieval grounding with four comments on a 30-line diff.
